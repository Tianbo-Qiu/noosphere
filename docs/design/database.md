# Database

All data lives in one Postgres database. The schema and the queries are written in SQL; the Go code that uses them is described in [Persistence layer](persistence.md).

## Postgres only

Noosphere supports exactly one database. Supporting several makes sense for software that other people deploy on the database they already run. Noosphere has one deployment, so it uses Postgres features directly instead of the common subset of several databases: `uuidv7()` IDs, `jsonb` columns, `IS NFC NORMALIZED` checks and transactional schema changes. All SQL stays in `db/` and `internal/db`, so the choice would be contained if it ever changed.

## Migrations

Schema changes are numbered SQL files in `db/migrations`, applied in order by goose. Each file has an Up part and a Down part that undoes it. A migration that has been applied is never edited; a later change gets a new file. goose runs each migration in a transaction, and Postgres can roll back schema changes, so a failed migration leaves no half-applied schema.

## Queries

SQL queries live in `db/queries`, and sqlc turns each one into a Go function with typed parameters and results. The SQL stays readable and is checked against the real schema, and Go gets compile-time types without an ORM.

## IDs and flexible data

Primary keys are [UUIDv7](https://www.rfc-editor.org/rfc/rfc9562) values generated by Postgres. They are unique without coordination and start with a timestamp, so new rows are inserted in order and indexes stay compact.

Data whose shape varies is stored as `jsonb`: an identity's traits, and each credential's config, whose shape depends on the credential type.

## Rules in the database

Constraints in the schema enforce the rules that must never be broken, whatever code path writes the row:

- an identifier is unique per credential type (`UNIQUE (type, identifier)`);
- an identifier belongs to a credential of the same type (a foreign key on `(credential_id, type)`);
- a stored identifier is already normalized: lowercase, trimmed, in Unicode NFC form, and not empty (a `CHECK` constraint).

Go does the full normalization with [PRECIS](../standards/precis.md) before writing; the `CHECK` is a safety net that catches any path that skipped it.
